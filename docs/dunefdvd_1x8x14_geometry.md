# DUNE FD-VD 1x8x14 geometry in wire-cell-bee3

The `DUNEFDVD1x8x14` class in
[`events/static/js/bee/physics/experiment.js`](../events/static/js/bee/physics/experiment.js) draws
the DUNE far-detector vertical-drift 1x8x14 workspace. This is the `dunevd10kt_1x8x14_3view_30deg`
geometry of the wcp-porting-validation `fdvd_sim` solar-neutrino and radiological samples
(`fdvd_sim/docs/02`, `03`).

A Bee event selects it with `"geom": "dunefdvd-1x8x14"`. The name contains `vd`, so `scene.js` applies
the vertical-drift rotation.

The older `dunefdvd-1x8x6` class is left untouched. It has 48 boxes and no photon detectors, and its
base alternating `driftDir` is wrong for an all-top-drift workspace.

## Layout

| item | value (cm, LArSoft global frame) | source |
|---|---|---|
| CRMs | 112. WCT anode ident `a` → y row `a % 8`, z column `floor(a / 8)` | Wire-Cell wires file `dunevd10kt_3view_30deg_v7_refactored_1x8x14.json.bz2` |
| x | cathode surface −325.0 to collection plane +325.07. **All anodes at +x** (top drift only) | `fdvd_sim/cfg/params-fdvd.jsonnet` (cathode −3250 mm), wires (W at 3250.7 mm) |
| y | 8 rows 167.9 cm tall, from −675.1 to +675.1, in abutting pairs; gaps of 1.7 cm at y = ±338.45 and 3.6 cm at y = 0 | per-CRM wire extents |
| z | 14 columns 148.92 cm long, from 0.85 to 2100.33, in abutting pairs; gaps between pairs of 1.7–4.2 cm | per-CRM wire extents |
| wire angles | U −60°, V +60°, W 0° (atan2(dz, dy)): PDVD's **top**-anode tilts | wires file |
| channel order | every plane of every CRM numbers channels along +z (segment-0 wires, CRMs 0/7/56/111) | wires file |
| drift speed | 0.160563 cm/µs (the LArSoft FD-VD value the sample drifted with) | doc 02 §1 |
| readout | 0 to 4250 µs, tick 0 at the neutrino time | doc 02 §3 |
| photon detectors | 184 X-ARAPUCAs in LArSoft OpDet order: 112 cathode (x −327.5, face x), 56 long-lateral (y ±743.3, orient 1), 16 short-lateral (z-end walls, orient 2) | v5 GDML via `fdvd_sim/stageA/opdet_geometry.py`, verified against 32 285 single-OpDet `recob::OpFlash` centres (max 7e-13 cm) |

The numbers are generated by `fdvd_sim/bee/make_bee_geom.py`. Its `--check` mode parses them back
out of this class and compares them with the wires file and the OpDet table:

```
python3 fdvd_sim/bee/make_bee_geom.py --check <bee3>/events/static/js/bee/physics/experiment.js
# 112 boxes max |d| = 0.000 cm, 184 OpDets max |d| = 0.002 cm -> PASS
```

## Drift direction, views and photon detectors

- **Drift direction.** `driftDir(i) = -1` for every box: the anode is on the +x side of every box, as for
  PDVD's top anodes. `op.js` therefore draws the red anode band (enabled for this class) at x = +325.
- **View angles.** `viewAngle = [60, 120, 0]`. This is PDVD's `[120, 60, 0]` with U and V swapped, i.e.
  what PDVD's `projView` produces for its top anodes. The base `projView` negates the angles when
  "Reverse Drift Axis" is toggled, which is the same U↔V swap modulo 180°.
- **Projection mirror.** `projMirror` stays at the base `false`, because channels run along +z on every
  plane, as in SBND.
  - **Not yet checked against an SP image.** Nothing FD-VD has been loaded in Bee so far.
- **Photon detectors.**
  - `opTPC` attaches each detector to the box nearest in (y, z). Every box has the same x centre, so
    the base nearest-in-x fallback would put all 184 on box 0.
  - The X-ARAPUCA outline now honours orient 2 (a z-end wall) in `helper.js` and `op.js`. No existing
    detector uses detType 2 with orient 2, so they are unchanged.
  - `op.js` also includes the class in the predicted-light offset.
  - `gui.js`'s "Show Ph. Det." list is unchanged. PDVD is not in it either.

## Deployment

A local change does not reach the live Bee server. Rebuild the Parcel bundle and deploy
(`docs/linux-deployment.md`) **before** any zip carries `"geom": "dunefdvd-1x8x14"`. Until then, the live
server falls back to MicroBooNE for the unknown name (`createExperiment`).
